## Recurring Server Issues

### Git pull blocked by untracked files
- The server sometimes has local untracked files that block `git pull`.
- Typical example:
  - `scripts/start-services.ps1`
- Fix pattern:
  - back up the local file
  - pull latest `main`
  - redeploy

### Services stopped after shell exit
- The app can stop if it is launched manually in a transient shell.
- Preferred fix:
  - run the shared startup script
  - keep the scheduled task enabled

### PowerShell command gotchas
- In PowerShell, prefer `npm.cmd` over `npm` when the shell policy interferes with `npm.ps1`.
- Use `git rev-parse --short HEAD` on the server before troubleshooting runtime issues.

### Frontend install/build failures
- The frontend install step has shown an `ENOENT` path creation failure under `frontend\node_modules\@t...`.
- Treat this as a dependency/install-state problem first, not a source-code bug.
- Preferred recovery path:
  - run `npm.cmd install` inside `frontend`
  - if it still fails, remove `frontend\node_modules` and reinstall
  - then run `npm.cmd run build`

## Mistakes To Avoid

1. Do not assume a build succeeded just because the repository changed.
2. Do not trust frontend hiding alone for permissions.
3. Do not merge upload changes without testing the real upload endpoint and the UI result.
4. Do not use async audio resume as the only path for click-triggered preview sounds.
5. Do not overwrite server-local untracked files during a pull without backing them up first.
6. Do not debug a live server without first checking the deployed commit hash.
